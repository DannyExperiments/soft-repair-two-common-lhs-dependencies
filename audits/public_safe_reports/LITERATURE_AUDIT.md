Checked 2026-11-27. High confidence in the exact source match and data-complexity scope. The bounded search found no matching prior lower bound for the two separately penalized dependencies. Publication priority remains unestablished.

- Carmeli, Grohe, Kimelfeld, Livshits and Tibi, *Database Repairing with Soft Functional Dependencies*, ACM Transactions on Database Systems 49(2), Art. 8 (2024), DOI 10.1145/3651156. The final indexed journal text gives the objective in §2 and explicitly lists the fixed set {A→B, A→C} as the first open case in §7. The official ICDT 2021 proceedings version gives the same question in §6 at printed p. 16:16, PDF p. 16. Its equation (1), §2.2, counts every retained unordered pair for each violated dependency separately and adds the weights of deleted facts. Numerical costs are binary rationals in the problem input; the relational schema and FD set are fixed. Direct journal PDF was unavailable in the checked routes, so no printed journal page number is asserted. [Final journal and §7](https://doi.org/10.1145/3651156) · [Official conference version](https://drops.dagstuhl.de/storage/00lipics/lipics-vol186-icdt2021/LIPIcs.ICDT.2021.16/LIPIcs.ICDT.2021.16.pdf#page=16)
- Under hard constraints, the two FDs are equivalent to A→BC; one can retain a best (B,C) value per A-block. The source's §§4.2–4.3 distinguish this from softness, under which pairs can pay for one or both mismatches. The single-FD dynamic program and the soft matching-flow algorithm apply to different FD configurations. The matching generalization requires left-side coverage beyond the common {A} here. The source's pairwise discussion does not establish hardness for the common-left-side soft case. Known hardness for a chain such as {A→B, B→C} uses different conditions. [Conference proof and model](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ICDT.2021.16)
- Livshits–Kimelfeld–Roy's optimum subset repair dichotomy enforces hard FDs. The 2026 Kimelfeld–Livshits result classifies hard unary update repairs, which edit cells to enforce every FD. Both are distinct from deleting facts and charging each residual violation. [Hard optimal repairs](https://arxiv.org/abs/1712.07705) · [2026 update repair](https://arxiv.org/html/2608.15328v1)
- The recovered reduction from CLIQUE uses one A block, with a large finite state-independent penalty to enforce packing rather than feasibility. Sharing one C label per edge counts exactly the induced edges in the chosen full B blocks. The new hardness uses a numerical penalty supplied as input and also one common deletion cost supplied as input. Weights are polynomially bounded integers, and the second dependency penalty equals one. The result does not classify the case where all weights are fixed constants. [Karp's source](https://doi.org/10.1007/978-1-4684-2001-2_9)
